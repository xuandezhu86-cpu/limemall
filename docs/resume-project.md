# 简历项目描述模板（校招 / 实习 · Java 后端）

> **使用说明**
> 1. 下面所有数字都来自本仓库真实压测与验证（`docs/load-test-report.md`、`infra/tools/cache-bench.ps1`、`infra/tools/seckill-concurrency-check.ps1`），**没有编造**。但你换机器后值得自己重跑一遍，换成你自己的数字——面试官问"怎么测出来的"，你要答得上来。
> 2. 简历上的项目不要写成"我参与了"，个人项目就写个人项目，**别虚构实习经历或公司背景**。面试官最反感的是把课程项目包装成公司项目，一旦追问细节就穿帮。
> 3. 篇幅建议：**项目经历占 2~3 段，每段 3~5 条 bullet**，一条 bullet 只讲一件事，用"做了什么 + 怎么做的 + 什么结果"的结构。

## 一、标准版（推荐，直接可用）

**青柠商城 LimeMall —— 基于 Spring Cloud Alibaba 的电商微服务系统**（个人项目 · 2026.09 - 2026.10）

> 技术栈：Java 11 · Spring Boot 2.7 · Spring Cloud Alibaba（Nacos/Sentinel/Seata）· Spring Cloud Gateway · MyBatis-Plus · MySQL · Redis · RabbitMQ · Caffeine · Prometheus/Grafana · Zipkin · Docker Compose · JMeter

- **微服务架构**：将电商系统按业务域拆分为网关、商品、购物车、用户、交易、支付、秒杀 7 个服务，基于 Nacos 做注册与配置中心（抽取 4 份共享配置），网关统一 JWT 鉴权并向内部服务注入用户身份，服务间用 OpenFeign 调用；用 Docker Compose 编排 MySQL/Redis/RabbitMQ/Nacos/Seata/Sentinel 等 10 个容器，编写一键启动脚本（含启动失败自动重试与 JVM 堆上限），可在单机复现整套环境。

- **秒杀系统（独立开发）**：设计「Redis + Lua 原子预扣 → 令牌桶限流 → RabbitMQ 异步落库 → 定时对账补偿」的四层方案，把「校验库存 / 校验一人一单 / 扣减库存 / 记录买家」合并为一次 Lua 原子操作消除"先查后改"窗口，数据库侧用条件更新（`stock >= num`）与 `(activity_id, user_id)` 唯一索引兜底；**JMeter 实测 200 用户抢 100 件库存：恰好生成 100 笔订单、零超卖**，吞吐 105 TPS / 平均 1,442ms，相比数据库悲观锁同步方案（43.5 TPS / 3,472ms）**吞吐提升 2.4 倍、平均延迟下降 58%**。

- **商品详情多级缓存**：实现 Caffeine（本地）+ Redis（共享）两级缓存，针对性治理三类问题——**穿透**用 Redis 位图布隆过滤器（16M bit / 4 哈希）+ 空值缓存兜底，**击穿**用 SETNX 互斥锁 + 短自旋只放行一个线程回源，**雪崩**用过期时间随机抖动 + L1 短 TTL；多实例本地缓存一致性通过 RabbitMQ fanout 交换机广播失效解决（每实例一个匿名队列）；**压测 50 并发 30 秒：走缓存 13,383 TPS / 平均 3.4ms / P95 8ms，直连数据库 2,689 TPS / 平均 17.1ms / P95 31ms，吞吐约 5 倍，40 万次请求仅回源数据库 3 次**。

- **可观测性建设**：为全部服务接入 Actuator + Micrometer 暴露 Prometheus 指标（Actuator 走独立管理端口，与业务端口隔离），埋点 10 个自定义缓存指标（各级命中、回源次数、布隆拦截、锁重建等）；基于 Prometheus + Grafana 搭建 12 个监控面板与 7 条告警规则（服务掉线、5xx 速率、接口 P95 超 500ms、JVM 堆超 85%、连接池饱和、缓存命中率过低等）；接入 Sleuth + Zipkin 实现跨服务链路追踪（traceId 贯通 Feign/RabbitMQ/Redis），一次下单可还原 20+ span 的完整调用树。

- **性能压测与调优**：使用 JMeter 非 GUI 模式编写参数化压测脚本（同一脚本通过参数切换"优化实现 / 基线实现"），配套结果解析脚本自动产出吞吐、P50/P95/P99 与错误率对比表；过程中定位并修复 Nacos 启动期 gRPC 超时、多 JVM 内存压垮机器、Springfox 与 Spring Boot 2.6+ 不兼容导致服务无法启动、HTTP 延迟直方图默认关闭导致 P95 指标为空等问题。

## 二、精简版（简历空间紧张时用，3 条）

**青柠商城 LimeMall —— Spring Cloud Alibaba 电商微服务系统**（个人项目）

> Java 11 · Spring Cloud Alibaba · Gateway · Redis · RabbitMQ · MySQL · Prometheus · Docker

- 按业务域拆分 7 个微服务，Nacos 注册与配置中心 + 网关统一 JWT 鉴权，Docker Compose 一键编排 10 个中间件容器。
- **独立设计秒杀链路**（Redis+Lua 原子预扣、令牌桶限流、MQ 异步削峰、一人一单、对账补偿），压测 200 用户抢 100 件**零超卖**；吞吐较数据库悲观锁方案提升 2.4 倍、平均延迟下降 58%。
- **实现商品详情两级缓存**（Caffeine + Redis，含布隆过滤器防穿透、互斥锁防击穿、TTL 抖动防雪崩、MQ 广播解决多实例一致性），压测吞吐 **13,383 TPS**（直连 DB 为 2,689 TPS），40 万次请求仅回源数据库 3 次。

## 四、不同岗位侧重的裁剪建议

| 投递方向 | 建议保留 | 可以弱化 |
|---|---|---|
| 后端开发（通用） | 秒杀 + 缓存 + 分布式事务 | 可观测性细节 |
| 基础架构 / 中间件 | 缓存一致性、MQ 削峰、Seata AT 原理 | 业务功能罗列 |
| 高并发 / 性能方向 | 压测数据、调优过程、瓶颈分析 | CRUD 功能 |
| 运维 / SRE 方向 | 可观测性（指标/告警/链路）、Docker 编排、一键脚本 | 业务逻辑 |

## 五、写法禁忌（很重要）

| ❌ 不要这样写 | ✅ 应该这样写 |
|---|---|
| "负责公司秒杀系统的开发"（虚构实习） | "独立设计并实现秒杀服务" |
| "性能提升明显" | "吞吐从 2,689 TPS 提升到 13,383 TPS（约 5 倍）" |
| "使用了 Redis 缓存" | "用布隆过滤器防穿透、SETNX 互斥锁防击穿、TTL 抖动防雪崩" |
| "熟悉分布式事务" | "下单链路用 Seata AT 保证跨三库一致性；秒杀刻意不用全局事务，改用最终一致 + 对账补偿" |
| 堆技术名词（"精通 Spring Cloud 全家桶"） | 每个技术点都挂一个**你亲手解决的问题** |
| 写"团队协作"但只有一个人 | 写清哪些是课程基础版、哪些是你自己新增的模块 |

## 六、面试开场 30 秒自述（背下来）

> "我做的这个项目是一套 Spring Cloud Alibaba 的电商微服务系统，包含商品、购物车、交易、支付等 7 个服务。
> 除了基础的微服务拆分，我自己重点做了三块：**第一是秒杀链路**，用 Redis+Lua 做原子预扣、令牌桶限流、MQ 异步削峰，压测 200 个用户抢 100 件商品，做到了恰好 100 单、零超卖，吞吐比直接用数据库悲观锁的方案高 2.4 倍；**第二是商品详情的两级缓存**，用 Caffeine + Redis 加布隆过滤器和互斥锁，把接口吞吐从 2,689 TPS 提到 13,383 TPS，40 万次请求只回源数据库 3 次；**第三是可观测性**，接了 Prometheus + Grafana 的指标告警和 Zipkin 的链路追踪，并用 JMeter 做了完整压测，压测脚本和原始数据都在我仓库里。
> 您想先听哪一块？"

> 💡 最后一句"您想先听哪一块"很重要——**把选择权交给面试官**，他大概率会挑秒杀或缓存，而那正是你准备最充分的地方。
